## 团队成员

| **产品经理 (PM)** | 分析需求，写PRD，规划功能优先级，验收测试反馈，编写/更新用户手册MD文档 | PRD文档、功能列表、用户手册文档 |

| **系统架构师 (Architect)** | 根据PRD设计架构方案，拆分任务分配给开发 | 架构设计文档、任务分配 |
| **技术架构师 (TechArchitect)** | 负责代码架构治理、技术债评估、代码评审问题归类与修复方案设计，将方案交给Architect统筹 | 技术架构治理文档、代码重构方案 |
| **开发专家1 (Dev1)** | 实现架构师分配的模块，修复BUG | 代码实现 |
| **开发专家2 (Dev2)** | 实现架构师分配的模块，修复BUG | 代码实现 |
| **开发专家3 (Dev3)** | 实现架构师分配的模块，修复BUG，侧重代码质量优化与评审问题修复 | 代码实现 |

| **红队用户1 (Red1)** | 以渗透测试新手视角使用wscan，测试基本扫描流程易用性，反馈给PM | 易用性反馈报告（入门流程） |
| **红队用户2 (Red2)** | 以经验丰富的渗透测试师视角使用wscan，测试高级功能和定制化能力，反馈给PM | 高级用户反馈报告（进阶功能） |
| **红队用户3 (Red3)** | 测试注入类插件实际检测效果，记录漏报误报，反馈给PM | 检测效果报告（注入类） |
| **红队用户4 (Red4)** | 测试RCE/反序列化类插件实际检测效果，记录漏报误报，反馈给PM | 检测效果报告（RCE类） |

### 第1步：产品经理分析
- 分析 wscan 现有代码和配置
- 对照 config.yaml 中声明的功能 vs 实际实现
- 编写 PRD：列出所有待实现/需修复的功能
- 编写/更新用户手册MD文档（README.md、README_CN.md、doc/目录下的使用指南）

### 第2步：架构师设计
- 审阅 PRD
- 设计技术方案，明确文件改动范围
- 将任务拆分并分配给 Dev1 和 Dev2

### 第3步：开发实现
- Dev1 和 Dev2 各自实现分配的模块
- 编写代码，确保编译通过

### 第3.5步：安全审阅（第一轮，与开发并行）
- Sec1 审阅注入类插件代码（XSS/SQLi/CMDi/SSRF/PathTraversal/CRLF等）
- Sec2 审阅RCE类插件代码（Shiro/FastJSON/XXE/Struts/ThinkPHP/XStream等）
- 重点找出：
  - **误报点**：检测逻辑过于宽泛，正常请求可能被标记为漏洞
  - **漏报点**：已知漏洞模式未被覆盖，payload不完整
  - **逻辑缺陷**：验证步骤不足、绕过方式未考虑
- 将问题反馈给架构师，由架构师决定修复方案并分配给开发

### 第3.7步：安全审阅（第二轮，修复后验证）
- Sec3 二次审阅 Dev1 修复后的代码（注入类 + Shiro）
- Sec4 二次审阅 Dev2 修复后的代码（RCE类 + 基础设施）
- 重点审查：
  - **修复验证**：第一轮发现的问题是否被正确修复
  - **回归问题**：修复是否引入了新的误报或漏报
  - **代码质量**：新增代码是否遵循安全编码规范
  - **边界条件**：新实现是否处理了异常情况和边界值
- 将问题反馈给架构师

### 第3.9步：红队用户实战测试 + 设计师UI/UX评审
- Red1：以渗透测试新手视角，测试从安装到完成首次扫描的全流程易用性
- Red2：以资深渗透测试师视角，测试高级配置、自定义插件、MCP接口等进阶功能
- Red3：针对注入类漏洞场景（XSS/SQLi/CMDi等），测试实际检测效果，记录漏报和误报
- Red4：针对RCE/反序列化场景（Shiro/FastJSON/XXE等），测试实际检测效果，记录漏报和误报
- Red5：测试输出报告质量、爬虫覆盖率、反连平台可靠性等综合能力
- **Designer**：审阅所有用户可见的UI输出，包括：
  - 控制台输出样式（色彩方案、排版、信息层级、进度展示）
  - HTML报告视觉设计（布局、配色、字体、表格样式、响应式适配）
  - 信息架构（漏洞信息展示是否完整清晰、是否有视觉引导）
  - 一致性（控制台与HTML报告的信息是否一致、术语是否统一）
  - 可访问性（色盲友好、对比度、字体大小）
- 所有问题统一反馈给 PM，由 PM 更新 PRD 并推动下一轮迭代
- Red1：以渗透测试新手视角，测试从安装到完成首次扫描的全流程易用性
- Red2：以资深渗透测试师视角，测试高级配置、自定义插件、MCP接口等进阶功能
- Red3：针对注入类漏洞场景（XSS/SQLi/CMDi等），测试实际检测效果，记录漏报和误报
- Red4：针对RCE/反序列化场景（Shiro/FastJSON/XXE等），测试实际检测效果，记录漏报和误报
- Red5：测试输出报告质量、爬虫覆盖率、反连平台可靠性等综合能力
- 所有问题统一反馈给 PM，由 PM 更新 PRD 并推动下一轮迭代
- QA 对照 PRD 和架构文档逐项测试
- 找出未实现/有问题的功能
- 生成测试报告反馈给 PM

### 第5步：迭代
- PM 根据测试报告更新 PRD
- PM 根据新实现的功能更新用户手册文档
- 进入下一轮迭代
